# 声学避坑与实战复盘指南

这份文档记录了我们在反复盲听对比与真实外放测试中定位出来的 **6 个最常见「AI 味 / 电音」根因** 及对应的工程解法，供调优参数或自建本地推理时参考。

---

## 1. 为什么克隆出来会有「电音感」？

### 根因 A：对参考音频做过 `atempo` 变速拉伸或二次有损压缩
- `ffmpeg` 的 `atempo` 基于 WSOLA 波形拼接算法，在正常播放中轻微提速 1.05×–1.08× 人耳不易察觉，但波形相位已经产生微弱周期性毛刺。
- 若再叠加二次 MP3 编码或连续两次 `atempo` 拉伸，送进零样本克隆模型后，**模型会把这些相位毛刺误认为说话人的固有音色特征**，并在后续每一句合成里放大成明显的「电音/金属丝感」。
- **正确做法**：`prep-ref` 永远直接读取最原始录音无损解码，**不变速、不压缩、不做染色 EQ**，仅做去直流与 `70 Hz` 2 阶高通。

### 根因 B：低帧率离散码本声码器的高频重建颗粒
- 24 kHz / 12 Hz 离散 token 声码器在单段超过 15 秒的长文本上，高频谐波容易出现细碎的电子颗粒感。
- **正确做法**：优先使用原生 **44.1 kHz 连续扩散模型（如 VoxCPM2）**，并按自然语义把长稿拆成 10–17 秒/段生成。

## 2. 为什么笔记本扬声器外放会「发刺、听着累」？

- 很多播客/人声教程习惯在 `2.5–4 kHz` 提亮 `+2 ~ +3 dB` 来增加“临场清晰度”。
- 但笔记本电脑与手机的小口径扬声器本身在 `2–4 kHz` 存在剧烈共振峰，在克隆人声上叠加 `2.8 kHz` 提亮会把残余声码器高频颗粒直接推到刺耳区间。
- **正确做法**：取消 `2–4 kHz` 提亮，保持原生 `44.1 kHz` 全频带通透感，只做极轻的 `300 Hz -1.0 dB` 去盒音与 `6.8 kHz -1.6 dB` 柔压齿音，配 `1.35:1` 极轻压缩，最终响度定在耐听舒适的 **`-15.5 LUFS / -1.8 dBTP`**。

---

## 3. 为什么停顿处一听就是「拼接出来的」？

- 多数 TTS 或拼接脚本会在句间直接插入全零数组（`-240 dB` 纯数字静音），而说话片段内部往往自带 `-55 ~ -65 dB` 的微弱房间底噪。
- 声音在 `-60 dB` 底噪与 `-240 dB` 死寂之间反复横跳，就是最刺耳的「静音门抽吸感（noise-gate pumping）」。
- **正确做法**：
  1. 在 `prep-ref` 阶段先用原音频提取的真实底噪填补参考录音内部的 `-240 dB` 静音黑洞；
  2. 在 `master` 阶段铺设一条 `-62 dBFS`、低通至 `3.8 kHz` 的温暖棚拍室音（语音响起时自动平滑闪避，不叠加底噪），让整条 70–90 秒音频听起来像一次连贯录音。

## 4. 为什么明明没改音色，段与段之间却像换了话筒？

- 使用 `use_prompt_text=False`（仅借本人声纹 + 自然语言风格控制）时，如果每段分别写不同的情绪提示词（例如一段写“稳重”、下一段写“欣喜轻快”），扩散模型往往会顺带改变胸腔共振比例与近讲距离，造成段间音色跳变。
- **正确做法**：全篇所有分段**严格使用一字不差的同一条 `control_instruction`**，把语气起伏交给文案本身的句式（设问、转折、短长句穿插）自然驱动。

---

## 5. 句尾被「吞字」与中文多音字误读

- **防吞字**：用 `-40 dB` 找开口、用更宽松的 `-46 dB` 找收声点（保留字尾自然气声）；若检测到模型自己在字尾一刀切（收声前 20 ms 仍在 `-35 dB` 以上），提前 55 ms 做余弦淡出把断崖抹圆。
- **多音字**：科技口播中的「校准」在「自校准」等组合里常被误读成 `xiào`。在 JSON 脚本的 `say` 字段写「自较准」（或启用内置 `DEFAULT_POLYPHONE_MAP`），即可在不改字幕原文的前提下确保读音准确；每次成片后务必全篇亲耳回听，有瑕疵仅用 `--only N` 单段返修。

## 6. Windows 端自动化播放的两个隐蔽坑

1. `Start-Process file.mp3`：在未固定 `.mp3` 默认关联的 Windows 机器上会弹出「选择一个应用以打开此 `.mp3` 文件」对话框，无法自动出声。
2. WinGet 安装的 `ffplay`：在 PowerShell 传递含中文路径的参数时容易因代码页编码差异直接闪退。
3. **可靠解法**：`voice_pipeline.py play` 先用 `ffmpeg` 将目标音频转为纯 ASCII 路径的 `%TEMP%\nvc_playback.wav`，再以独立后台 Python 进程调用 `sounddevice` 直连系统默认扬声器输出，并等待 `1.8s` 校验播放进程存活。
